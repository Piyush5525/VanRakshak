# Security

* **Authentication**: `AUTH_MODE=jwt` validates HS256 bearer tokens (signature, expiry, audience, `sub`, `role` claim). `AUTH_MODE=dev_header` (trusts an `X-Role` header) is **refused at startup when `ENVIRONMENT=production`**. HS256 with a shared secret (min 32 chars) is a stop-gap; use an OIDC provider with asymmetric keys for a real deployment. `app.core.security.issue_token` exists for operators and tests.
* **Authorisation**: roles `admin`, `reviewer`, `officer`, `read_only`, enforced per route; a global guard requires a valid identity on every `/api` call except the three signed provider webhooks, which authenticate by secret/signature. Audit log and reports are role-gated; station contacts are masked.
* **Rate limiting**: in-memory sliding window per client IP (`RATE_LIMIT_PER_MINUTE`). Single-process only; use a gateway for multiple workers.
* **Correlation IDs and structured JSON logs** on every request. Unhandled errors return a generic body plus the correlation ID; internals stay in logs. Provider URLs containing keys are never echoed.
* **Input limits**: GeoJSON type/coordinate/vertex validation, raster and region pixel caps, raster paths confined to `RASTER_DIR` (path traversal rejected), job windows bounded.
* **Secrets**: only in environment / `.env` (git-ignored); `.env.example` has no values. HTTP-client request logging is forced to WARNING because Mapbox and FIRMS keys are carried in URLs. The browser receives only a public `pk.` Mapbox token (`/system/client-config`); a secret `sk.` token is never returned. Tests blank every provider key so they cannot spend real quota or send real messages. Anything pasted into chat or committed should be treated as exposed; rotate keys if that happened.
* **Untrusted data**: provider responses and ingested record text are stored and displayed, never executed or used as instructions; PDF text is escaped.
* **Audit**: sensitive actions append to `audit_events`. It is append-only by convention in SQLite; there is no database-level immutability.
* **Uploads**: evidence files are limited to a type allow-list and 10 MB, images/PDFs are signature-checked, stored under server-generated names (user filenames are sanitised metadata only), hashed with SHA-256, served with `nosniff`, and every download is audited. CSV exports neutralise spreadsheet formula injection.
* **Location privacy**: navigation needs explicit consent; only the latest position and summary figures are stored, and the last position is deleted at session end. Station contacts are masked in API responses. The browser's rendered content is HTML-escaped by a tagged-template helper; user text never reaches `innerHTML` unescaped.
* **Field reports**: hazards reported by officers are unverified until a reviewer/admin verifies them; a field report cannot self-verify.
* **Known gaps**: no HTTPS termination (use a reverse proxy), no per-user identities beyond the role claim, no retention/deletion jobs, no sensitive-species masking because no biodiversity layer is ingested, SQLite rather than PostGIS.
